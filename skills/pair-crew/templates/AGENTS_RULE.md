# 常驻规则片段（给不扫描 skills 目录的宿主）

把下面「规则开始」到「规则结束」之间的内容整段贴进宿主的常驻指令
（`CLAUDE.md` / `AGENTS.md` / 项目说明 / 用户规则；宿主若支持「用户提交提示词」钩子，
按宿主文档注入同一段文本）。先把 `<SKILL.md 的绝对路径>` 换成实际路径。

--- 规则开始 ---

## pair-crew：写代码 / 改代码前必走

只要我提出要写新代码、加功能、修改现有代码、修 bug、重构、补测试、改接口 / UI / 脚本，
你必须先读 `<SKILL.md 的绝对路径>` 并遵循它，**不需要我点名 pair-crew**。
读完之后第一动作是按它的 §0 出一份启动确认单：我读到的项目现状（带文件 / 表 / 流程证据）、
目标与不做、有锚点的疑问、任务拆分、测试用例草案；等我确认并冻结契约后才动手改代码。

小改动走轻量档（一页纸契约、开工记基线、提交前分类），不要为此开全套多 agent 派发；
有第二个写者、跨模块或涉及 UI 时按完整档走。不管哪一档，改一次代码就作废上一轮判定，
必须补一轮。

以下情况不要触发：纯问答、只读查代码 / 查日志 / 看报错、写文档、整理表格、闲聊；
以及我明确说「别走流程，直接改」时（回复里注明跳过了门禁）。拿不准就按触发处理。

--- 规则结束 ---

> 这段只是兜底。宿主支持 Agent Skills 时，优先把 `skills/pair-crew/` 放进宿主的 skills 目录，
> 让 frontmatter 的 `description` 做意图匹配。**两种挂法不要同时注入**，否则同一轮会加载两遍。
> 挂完用 `python skills/pair-crew/scripts/skill_meta_check.py` 自检，并新开一个会话验证。
